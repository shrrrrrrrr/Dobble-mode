## V1.3 — 本地账号与数据隔离（已完成）

**目标：** 在不接邮箱/手机号的前提下，让「账号是谁、数据属于谁」在本地先成立。

### 功能范围

- [x] 本地账号注册 / 登录（用户名 + 密码，仅当前设备）
- [x] 按 `userId` 隔离作品、反馈、社区、资料（`creator-life-v2:data:{userId}`）
- [x] 旧版 `creator-life-v1` 数据的一次性导入提示（用户确认后导入）
- [x] 更新 README，说明当前认证边界与运行方式
- [x] 代码仓库推送到 `Dobble-mode`，打 `v1.3.0` 标签

### 明确不做

- 邮箱验证码、手机号登录、SMTP 配置
- Supabase 真实连接与云端同步
- 专业模式

### 验收标准

- 可注册两个不同本地账号，数据互不可见
- 刷新页面后会话保持，退出后需重新登录
- `npm run build` 通过

## V1.4 — 短期回看产品化（下一版本）

**目标：** 把「本周回看」从 demo 变成可验收的短周期回忆体验。

### 功能范围

- [ ] 与用户确认：正式名称（本周 / 七日 / 月度）、周期规则、时区
- [ ] 按真实日期范围过滤作品与反馈（替换当前固定示例日期）
- [ ] 无数据 / 数据较少时的空状态与引导文案
- [ ] 在代码或配置中标注可替换的叙事文案位置（方便产品方填写）
- [ ] 更新 `docs/MEMORY_REPORT_TODO.md`，与实现对齐

### 明确不做

- 年度年报
- 分享图片/视频导出（可列入 V1.5 候选）
- 回看内容接入真实 AI 讲述

### 验收标准

- 只有本周（或确认周期内）的作品/反馈进入回看
- 翻页、返回、重放流程完整
- 文案位置清晰，便于后续替换

## V1.5 — 社区与资料体验加固

**目标：** 在仍为本地单设备的前提下，修社区身份模型和资料相关体验债。

### 功能范围

- [ ] 社区帖子作者改为稳定 `userId`，展示时 join 当前昵称（改昵称后旧帖仍属本人）
- [ ] 反馈「记录时刻」：让用户选择类型并输入内容，而非纯示例数据
- [ ] 图片写入 LocalStorage 的配额保护与错误提示
- [ ] 表单校验与操作失败的可理解提示（压缩失败、存储满等）
- [ ] 徽章仍保持 UI 占位，不设计获取规则

### 明确不做

- 多用户真实社区后端
- Markdown / 富文本
- 视频上传

## V2.0 — 云端数据层（认证方案待定）

**目标：** 在账号身份确定后，把私有数据迁到 Supabase，保留生活模式全部已有能力。

> **前置条件：** 用户确认认证方案（本地账号映射 / 邮箱+密码 / 其他）。**本阶段不包含邮箱 OTP 与手机号登录**，除非你之后明确要求。

### 功能范围

- [ ] 抽出 `profile` / `works` / `feedback` / `community` Repository 层
- [ ] 连接「双模」Supabase 项目（`zsrhgtplolhxrbzxwfkq`），配置 `.env.local`（不提交密钥）
- [ ] 首个登录用户的本地数据导入云端（可回滚、不静默丢数据）
- [ ] 私有图片上传 `creator-media` 桶，路径 `{auth.uid()}/{filename}`
- [ ] 社区公共图片的独立存储/访问方案（不公开私有桶）
- [ ] 更新 `docs/SUPABASE_SETUP.md` 与 HANDOFF

### 明确不做

- 专业模式 UI
- 真实 LLM / Agent
- 跨平台自动抓数

## Git 版本管理约定

- **主分支：** `master`（生活模式主线）
- **标签：** `vMAJOR.MINOR.PATCH`，与上表里程碑对应
- **提交信息：** `feat:` / `fix:` / `docs:` / `chore:` 前缀，一句说清「为什么」
- **功能分支（可选）：** `feature/v1.4-weekly-recap` 等，合并回 `master` 后打标签
- **不推送至：** `creator-topic-library`（仅专业模式参考，保持只读）
